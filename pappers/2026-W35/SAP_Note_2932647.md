## 2. Symptom (Síntoma)

Está utilizando la funcionalidad **SAP BW/4HANA Model Transfer** de SAP Datasphere en combinación con su aplicación SAP BW/4HANA. Desea transferir **BW queries** desde SAP BW/4HANA hacia SAP Datasphere. Está buscando la lista actual de features **soportados** y **no soportados** de las *BW analytic queries* y de sus **BW InfoProviders** y **BW InfoObjects** subyacentes que quiere transferir.

> Esta nota SAP es relevante también para el Model Transfer hacia SAP Datasphere vía **SAP Datasphere, BW bridge**.

## 4. Reason and Prerequisites (Motivo y prerrequisitos)

La funcionalidad **SAP BW/4HANA Model Transfer** en SAP Datasphere es un **desarrollo en curso**, liberado en **múltiples oleadas (waves)**. Por lo tanto, la lista de features soportados y no soportados **cambia cada vez que se envía una nueva versión** de la funcionalidad a los tenants de SAP Datasphere.

---

## 5. Solution (Solución)

### 5.1 Advertencia de vigencia

> **PLEASE NOTE:** Esta nota SAP se **actualiza con frecuencia** cada vez que se hacen disponibles nuevas funcionalidades. La lista de features soportados y no soportados **cambia con el tiempo**.
>
> ➜ Consecuencia práctica: valide siempre la versión vigente de la nota en SAP for Me antes de tomar decisiones de diseño. Este documento refleja la **versión 18 (18.12.2025)**.

### 5.2 Alcance para SAP Datasphere, BW bridge

**SAP Datasphere, SAP BW bridge** utiliza las **SAP BW/4HANA Queries** para el Model Transfer. Por lo tanto, la lista de features soportados y no soportados **también es válida** para el Model Transfer vía SAP Datasphere, SAP BW bridge.

### 5.3 Comportamiento general ante features no soportados

La nota lista los features actualmente soportados en el escenario de SAP BW/4HANA Model Transfer en **tres niveles distintos**:

1. **BW analytic query** (nivel *Analytic Query*)
2. **InfoProvider** (nivel *CompositeProvider*)
3. **InfoObject**

**Regla general:** salvo que se indique lo contrario, los features **no soportados NO impiden** que la BW analytic query sea transferible de SAP BW/4HANA a SAP Datasphere; simplemente son **omitidos (skipped) y eliminados del objeto transferido** durante el proceso.

> ⚠️ **Excepciones a la regla general** (aquí el modelo **no puede transferirse** en absoluto): *Temporal Join*, *Input Parameters from SAP HANA views* y *Ambiguous & temporal join* a nivel CompositeProvider. Véase la tabla de la sección 7.

### 5.4 Desconexión del modelo transferido (sin sincronización)

**By design**, cualquier modelo transferido queda **desconectado** de cualquier cambio aplicado en SAP BW/4HANA **después** de que el modelo fue transferido.

➜ Si los cambios deben aplicarse al modelo transferido, **el proceso de transferencia debe ejecutarse nuevamente**.

### 5.5 Nota especial: nodos de jerarquía usados en restricted key figures

- Las **jerarquías se aplanan (flattened out) y se materializan** en el modelo transferido.
- Las **actualizaciones de los datos de jerarquía** en SAP BW/4HANA **no se reflejan** en los modelos ya transferidos.
- Los **nodos de jerarquía se aplanan hasta sus valores hoja (leaf values)** como una **lista plana de datos**.
- Esto **puede impactar el rendimiento (performance)** en algunos casos.

### 5.6 Restricción de InfoProvider en escenarios SAP BW/4HANA

Para escenarios de **SAP BW/4HANA**, **solo pueden transferirse las BW queries que utilizan un BW CompositeProvider (HCPR)**.

### 5.7 Soporte de jerarquías (Hierarchies)

Las jerarquías están soportadas mediante la **SAP Note 3478268 – "Releasing The Hierarchy Functionality For The Export Of Metadata To Datasphere"**.

SAP Datasphere **no soporta todos los features** de las jerarquías de BW. Restricciones concretas:

| # | Restricción |
|---|---|
| 1 | Los **nodos deben ser únicos** (Nodes must be unique). |
| 2 | Los **link nodes no están soportados**. |
| 3 | Las jerarquías con **estructura dependiente del tiempo (time-dependent structure)** se leen con la **fecha actual**. |
| 4 | En la **ayuda de valores (value help)** para jerarquías solo se verán aquellas jerarquías donde la **fecha actual esté incluida**. |
| 5 | SAP Datasphere **no soporta jerarquías dependientes de versión (version-dependent hierarchies)**. Por ello, la **versión de la jerarquía y el nombre de la jerarquía se concatenan** para servir como **identificador único**. |

## 8. Resumen ejecutivo (lectura rápida)

### 8.1 Bloqueantes duros — el modelo NO se puede transferir

1. **Temporal Join** en el CompositeProvider (funcionalidad ABAP).
2. **Ambiguous & temporal join** en el CompositeProvider (riesgo de duplicación de key figures).
3. **Input Parameters from SAP HANA views** en el CompositeProvider.
4. *(Escenario BW/4HANA)* Query que **no** se base en un **BW CompositeProvider (HCPR)**.

### 8.2 Degradaciones silenciosas — se transfiere, pero el feature se pierde

Todo el resto de la sección 7: los objetos se transfieren y el feature no soportado se **omite y elimina** del objeto resultante. Riesgo principal: **diferencias de resultados** entre la query original en BW/4HANA y el modelo en Datasphere sin ningún mensaje de error explícito.

Puntos de atención frecuentes:

- **Two structures** → queries con dos estructuras pierden la segunda.
- **Default filter** → solo sobrevive el *global filter*.
- **Unit conversion**, **Non-cumulative key figures**, **Stock coverage key figures**, **Business volume elimination** → lógicas de negocio que deben rehacerse en Datasphere.
- **Advanced formular operators** → cualquier fórmula que exceda `+ - * /` se pierde.
- **Display Attributes** y **navigation attributes con acceso no genérico** → se pierden a nivel InfoObject.

### 8.3 Comportamientos con impacto de diseño

| Tema | Comportamiento | Implicación |
|---|---|---|
| Sincronización | El modelo transferido queda **desconectado** de BW/4HANA | Cada cambio en origen exige **re-ejecutar la transferencia** |
| Jerarquías | Se **aplanan y materializan** hasta las hojas | Datos de jerarquía **congelados**; posible **impacto en performance** |
| Jerarquías version-dependent | No soportadas | Se **concatena versión + nombre** como identificador único |
| Jerarquías time-dependent | Se leen con la **fecha actual** | El *value help* solo muestra jerarquías vigentes hoy |
| Time dependency (InfoObject) | Solo **current date**, evaluado como `now()` | No hay soporte de **key date** |
| Variables | Fijadas vía toggle `RSDWC_CSN_NO_VARIALBE` o mapeadas a variables Datasphere | **En BW Bridge no es posible fijar valores** |

### Symptom

> You are using the SAP BW/4HANA Model Transfer functionality of SAP Datasphere in combination with your SAP BW/4HANA application. You want to transfer BW queries from SAP BW/4HANA to SAP Datasphere. You are looking for the current list of supported and unsupported features of BW analytic queries and their underlying BW InfoProviders and BW InfoObjects that you want to transfer.
>
> This SAP Note is relevant for Model Transfer to SAP Datasphere via SAP Datasphere, BW bridge too.

### Other Terms

> SAP BW/4HANA, SAP Datasphere, SAP BW/4HANA Model Transfer, SAP Datasphere, SAP BW Bridge

### Reason and Prerequisites

> The SAP BW/4HANA Model Transfer functionality in SAP Datasphere is an on-going development, released in multiple waves. The list of unsupported and supported features therefore changes whenever a new version of the feature is shipped to SAP Datasphere tenants.

### Solution

> PLEASE NOTE: This SAP Note is updated frequently whenever new functionalities are made available. The list of supported and unsupported features changes over time.
>
> SAP Datasphere, SAP BW bridge is using the SAP BW/4 HANA Queries for the Model Transfer. The supported and unsupported feature list is relevant for the Model Transfer via SAP Datasphere, SAP BW bridge.
>
> The following section lists the features currently supported in the SAP BW/4HANA Model Transfer scenario at different levels (BW analytic query, InfoProvider, InfoObject). If not indicated otherwise, unsupported features do not prevent the BW analytic query from being transferrable from SAP BW/4HANA to SAP Datasphere, but are simply skipped and removed from the transferred object during the process.
>
> By design, any transferred model is disconnected from any changes applied in SAP BW/4HANA after the model was transferred. If the changes need to be applied to the transferred model, the transfer process has to be started again.
>
> Special note concerning hierarchy nodes used in restricted key figures: Hierarchies are flattened out and materialized in the transferred model. Updates to the hierarchy data in SAP BW/4HANA are not reflected in any models that have already been transferred. The hierarchy nodes are flattened out into their leaf values as a flat list of data. This can impact performance in some cases.
>
> For SAP BW/4 HANA scenarios, only BW queries using a BW CompositeProvider (HCPR) can be transfered.
>
> Hierarchies are supported with SAP note 3478268 - 'Releasing The Hierarchy Functionality For The Export Of Metadata To Datasphere'. SAP Datasphere does not support all features of BW hierarchies. Nodes must be unique. Link nodes are not supported. Hierarchies with a time-dependent structure are read with the current date. In the value help for hierarchies you will see only hierarchies, where the current date is included. SAP Datasphere does not support version-dependent hierarchies. Therefore, the hierarchy version and the hierarchy name are concatenated to serve as a unique identifier.
