Two ways to lose

Moving a BW query into Datasphere, there are two ways to lose features. Only one of them tells you.

The one that warns you
The model is not transferred
Four situations stop the process outright. Annoying, but honest: you find out on day one.
Query not based on a CompositeProviderTemporal joinAmbiguous joinInput parameters from HANA views
Three of the four live in the CompositeProvider, not in the query. You can find them by reviewing the provider before touching anything.
The one that doesn't
The feature vanishes from the object
Everything else does transfer, and unsupported features are simply skipped and removed from the transferred object. No error, no warning.
Any formula beyond + − × ÷IFANDOR%%GT%CTSUMCTNOERRNDIVCOUNTTwo-structure queriesDefault filterExit variablesReplacement pathAuthorization variablesUnit conversionNon-cumulative key figuresDisplay attributes
A model with half a formula removed looks perfectly healthy.
Note 2932647
That list covers Model Transfer. For the Query Template Generator —the new tool, documented by SAP on July 30, 2026— no equivalent list has been published. Ask for it by name before you sign the roadmap.
What you validate is not that the object exists. It's that the number matches, cell by cell, against the original query.
Source: SAP note 2932647, version 18 (Dec 18, 2025). The note itself warns that the feature list changes with every wave of the functionality.
