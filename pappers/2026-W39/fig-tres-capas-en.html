Three layers, three responsibilities

This is how a CDS view consumed live by SAC is built. Each layer carries its own annotations; none does the work of another.

Layer 1
Dimension
One master per view. Key and text declared. No reporting logic.
@Analytics.dataCategory: #DIMENSION
@ObjectModel.representativeKey: 'Customer'
define view ZI_Customer as select from kna1 {
  key kunnr as Customer,
  @Semantics.text: true
      name1 as CustomerName
}
Layer 2
Cube
The facts, with associations to the dimensions. Every amount with its currency; every measure with its aggregation.
@Analytics.dataCategory: #CUBE
define view ZI_SalesCube as select from ZI_BillingItem
  association [0..1] to ZI_Customer as _Customer
    on $projection.Customer = _Customer.Customer {
  @ObjectModel.foreignKey.association: '_Customer'
  Customer,
  @Semantics.amount.currencyCode: 'TransactionCurrency'
  @DefaultAggregation: #SUM
  NetAmount,
  @Semantics.currencyCode: true
  TransactionCurrency,
  _Customer
}
Layer 3
Query
The only one SAC sees. It carries presentation decisions, not new joins. Tested in RSRT as 2CZCSALESQ.
@AbapCatalog.sqlViewName: 'ZCSALESQ'   -- name in the engine: 2CZCSALESQ
@Analytics.query: true
define view ZC_SalesQuery as select from ZI_SalesCube {
  @AnalyticsDetails.query.axis: #ROWS
  @AnalyticsDetails.query.display: #KEY_TEXT
  Customer,
  @AnalyticsDetails.query.axis: #COLUMNS
  NetAmount,
  @AnalyticsDetails.query.formula: 'NetAmount / BillingQuantity'
  0 as AveragePrice
}
If Sales asks for another price, you touch the query. If Finance asks for another currency, you touch the cube. If the customer name changes, you touch nothing.
Sources: SAP Help, Analytics Annotations (SAP NetWeaver 7.5) · SAP Help, Live Data Connections to SAP S/4HANA. Example code, simplified.
