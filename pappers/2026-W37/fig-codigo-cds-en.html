The lines that decide the outcome

The cost centre attributes extractor, trimmed down. Two declarations make it extractable, one names the representative field, and the last one cuts the language field.

CDS view · cost centre attributes extractor
@AbapCatalog.sqlViewName: 'ZVCOSTCENTER'
@EndUserText.label: 'BW 0COSTCENTER_ATTR — cost centre attributes'

// The two declarations that make the view extractable
@Analytics.dataCategory: #DIMENSION
@Analytics.dataExtraction.enabled: true

// Points at the field alias, not its source name
@ObjectModel.representativeKey: 'KOSTL'

define view ZI_CostCenter_Attr_BW
  as select from I_CostCenter as _CC
    left outer to one join CSKS as _Z
      on  _CC.ControllingArea = _Z.KOKRS
      and _CC.CostCenter      = _Z.KOSTL
      and _CC.ValidityEndDate = _Z.DATBI
{
  // Compound key: controlling area + cost centre + validity
  key _CC.ControllingArea    as KOKRS,
  key _CC.CostCenter         as KOSTL,

  // The "valid to" goes inside the key; the "valid from", outside
  @Semantics.businessDate.to: true
  key _CC.ValidityEndDate    as DATETO,

  @Semantics.businessDate.from: true
      _CC.ValidityStartDate  as DATEFROM,

  // ... seventy-odd attributes: organisation, blocks ...

  // The language field: break the LANG type and rename it (KBA 3219389)
      cast( left( _Z.SPRAS, 1 ) as abap.char( 1 ) ) as ZZSPRAS
}
Names and structure are illustrative. Highlighted: the two annotations that enable extraction, and the cut that disables the language-field flag.
